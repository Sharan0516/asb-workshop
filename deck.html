What a Skill IS

A skill is a folder. With markdown in it.

That's it. That's the whole thing.

# The entire Legal Reviewer skill on my machine:

~/.claude/skills/legal-reviewer/
├── SKILL.md              # the recipe (38 lines)
├── examples/
│   ├── nda-template.md
│   └── msa-template.md
└── output-format.md      # the deliverable shape

You can read it. You can edit it. You can share it with a friend like a recipe. No code, no compilation, no deployment.

Claude Code for Business7
Anatomy

What's inside SKILL.md

---
name: legal-reviewer
description: Review contracts and
  surface risks, redlines, and questions
when_to_use: User shares a PDF or
  asks to review a contract
---

# What this skill does

When the user shares a contract:

1. Read the document.
2. Identify clauses that are
   non-standard or risky to a buyer.
3. Suggest specific redlines.
4. List 3 questions to raise with
   counsel before signing.
5. Save as a one-page brief to
   ~/contracts/{name}-{date}.md

# Tone
Plain English. Skip legalese.
Flag anything I'd regret signing.

Two sections. That's it.

Frontmatter
Metadata at the top. Name and description. This is how Claude decides when to use this skill.
Body
Plain-English instructions. Treat it like a note to a smart colleague on their first day.

If you can write a paragraph explaining how you do your job, you can write a skill.

Read This Before You Build

Power comes with rate limits.

Quick show of hands: who's been rate-limited or flagged by LinkedIn, Gmail, or a CRM? Automation amplifies. Cross a ceiling and you get flagged, suspended, or banned. Permanently.

ChannelDaily limitIf you exceed
LinkedIn connection requests20–25Restriction, then permanent ban
LinkedIn messages (1st degree)50Soft flag, reduced reach
Cold email (warmed inbox)50Spam folder, sender reputation hit
Cold email (new inbox)Start at 10, ramp over 4 weeksDomain blacklist
Auto-apply5–10 roles you actually wantRecruiter blacklist (spray equals death)
Three rules. Always.
1. Never auto-send to a real human without human review.
2. Respect captchas. They exist for a reason.
3. The skill is your assistant, not your replacement.

Claude Code for Business19
Best Practices

Four things I've learned the hard way

1. Always review before sending.
Drafts to file. Human eyes before any human reads it. Skills produce drafts, never auto-send.
2. Save preferences as you discover them.
When Claude does something you want every time, say so. The memory file is your training data.
3. Think like your agent.
When it misfires, ask: what did Claude actually see in its context? Its mistakes make sense from inside.
4. Outputs are files. Always.
Don't let work disappear into chat history. Every skill saves a deliverable to disk. Searchable, shareable, attachable.
The one rule above all rules
Never store secrets (API keys, passwords, financial credentials) in skill files, memory files, or anything that could end up on someone else's screen.
