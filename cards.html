# Card 1 — Create the Job Hunt Copilot skill

Create a new skill called "job-hunt-copilot" at
~/.claude/skills/job-hunt-copilot/

The skill should accept any job URL as input, including:
- LinkedIn job postings
- Lever, Greenhouse, Workday, Ashby career pages
- Any company's own career site

For each job URL, the skill should produce:
1. A parsed copy of the job description
2. A version of my resume tailored specifically to this role (ATS-friendly, mirrors the JD's keywords)
3. A personalized cold email draft to send to the hiring manager
4. A LinkedIn connection request note (under 280 characters)
5. Public-web research on the likely hiring manager (do NOT scrape LinkedIn directly)

Save all outputs to:
~/claude-outputs/job-hunt/{company-slug}-{YYYY-MM-DD}/

Maintain a master tracker at:
~/claude-outputs/job-hunt/tracker.xlsx
with columns: Date, Company, Role, JD URL, Hiring Manager, Status, Output Folder

CRITICAL RULES:
- Never auto-send any message. All outreach is drafts only.
- Always show me the file paths after each run so I can find what was produced.
- Respect rate limits if I ever ask for batch mode (max 20 connection requests/day, 50 emails/day).

Write the SKILL.md file with proper frontmatter (name, description, when_to_use). When done, show me the SKILL.md content so I can read what you built.
Done when:
  • Claude shows you the SKILL.md file it created
  • You can see frontmatter (name, description) at the top
  • You can see numbered workflow steps in the body
Read the SKILL.md. Seriously. It's only about 60 lines and reading it will teach you more than any lecture about how skills work.

# Card 2 — Add resume memory

Update the job-hunt-copilot skill so that:

1. The first time it runs, it checks for a saved resume at:
   ~/.claude/projects/-Users-{me}/memory/job-hunt-resume.md

2. If no resume is found, it asks me to either:
   - Paste my resume as plain text, OR
   - Provide a path to a PDF/DOCX of my resume

3. Save the resume to the memory file above so all future runs use it automatically. Never re-ask.

4. On every run, use the saved resume to produce a tailored version for the specific job description. The tailored version should:
   - Mirror keywords from the JD (ATS optimization)
   - Reorder bullets to surface most-relevant experience first
   - Trim experience that's irrelevant to this role
   - Stay under 1 page

Show me the updated SKILL.md when done.
Done when:
  • SKILL.md now mentions checking the memory file for a saved resume
  • The skill knows to ask for it once, save it, and never re-ask
The memory pattern is the single most powerful thing in this workshop. Use it in every skill you ever build.

# Card 4 — Save tone preferences

For the job-hunt-copilot skill, save these preferences to memory so every future run follows them automatically:

Cold email tone:
- Warm and conversational, never corporate-stiff
- Lead with WHY this specific role and this specific company, not generic enthusiasm
- One concrete reference to something the company recently did or said
- Maximum 120 words
- Always end with a soft, single CTA (15-min coffee chat or quick call)

LinkedIn note:
- Maximum 280 characters (LinkedIn's hard limit is 300, leave buffer)
- One reason for connecting that isn't "I want a job"
- No emojis

Universal rules:
- Never use em dashes. Use commas, periods, or restructure the sentence.
- Never claim experience I don't have on my resume.
- Never use words like "leverage", "synergize", or "passionate about".
- If unsure about a fact, leave it out rather than guess.

Save these preferences to a memory file the skill reads on every run.
Done when:
  • Claude confirms the preferences were saved to memory
  • Tells you the path to the memory file
Run Card 3 again. On a different job. Notice how the second draft already feels more like you. This is compounding.

# Card 6 — Add browser auto-fill (Tier 2)

Extend the job-hunt-copilot skill to optionally use Playwright to open the job's apply page in a browser and pre-fill the application form.

Behavior:
- Only triggered when I add --apply to my request (e.g., "use job-hunt-copilot on URL --apply")
- Detects whether the apply URL is on a supported site (Lever, Greenhouse, Ashby)
- Opens the apply page in a visible browser window (not headless)
- Pre-fills: name, email, phone, LinkedIn URL, resume upload, cover letter (use the cold email draft as cover letter content)
- For any field that requires judgment (custom essays, salary expectations, why-this-company), STOP and ask me before filling
- NEVER click the Submit button. Leave the page open for me to review and submit manually.

If the site is unsupported, fall back to: open the apply URL in my default browser and tell me what to fill where.

Install playwright if not already installed.

Update SKILL.md to document the new --apply flag.
This card may install Playwright. First-time installs can take 1 to 2 minutes. The browser window that opens IS your browser. Don't close it during the demo.
Card 7 · Bonus 2

Batch mode (10 jobs at once)

Paste multiple URLs. Claude fans out via sub-agents, processes all in parallel, returns one consolidated summary.

This card teaches the skill how to handle a list of jobs.

# Card 7 — Add batch mode (Tier 2)

Extend the job-hunt-copilot skill to support batch mode.

Behavior:
- Triggered when I provide more than one job URL in a single request, OR when I add --batch to my request
- Spawn one sub-agent per job URL (use the Agent tool)
- Each sub-agent runs the full pipeline for its assigned job (parse JD, tailor resume, draft email and LinkedIn note, research hiring manager, save to its own folder)
- After all sub-agents complete, the parent agent:
  1. Updates the tracker xlsx with one row per job
  2. Produces a single summary report at ~/claude-outputs/job-hunt/batch-{date}.md showing all jobs processed and a one-line status per job
  3. Highlights the 3 jobs with the strongest fit based on resume keyword overlap

Rate limit safety:
- Maximum 10 jobs per batch
- If more than 10 URLs are provided, process the first 10 and tell me the rest are queued
- Add a 5-second delay between sub-agent launches to be polite to job sites

Update SKILL.md to document batch mode.
This is your first sub-agent skill. Notice how the same pattern (skill orchestrating sub-agents) underpins everything from research to outreach to data pipelines.
Card 8 · Bonus 3

Build Meeting Prep Copilot (one paste)

A different skill. Same pattern. Paste once, get a working meeting-brief skill you'll use every week.

The Job Hunt build is hiring-focused. This card proves the pattern generalizes: swap the domain, keep the architecture, get a new skill in a single prompt.

# Card 8 — Build Meeting Prep Copilot

Create a new skill called "meeting-prep" at ~/.claude/skills/meeting-prep/

The skill should accept any of the following:
- A calendar invite pasted as text
- A path to a .ics file
- A list of attendees + subject + date

For each meeting, produce a one-page brief with:
1. Attendee profiles — title, company, public background, one memorable detail per person (no LinkedIn scraping, use public web search)
2. Company context — what they do, recent news, competitive position
3. Likely agenda — inferred from subject line and attendee mix
4. Five smart questions to ask
5. Three things I should have ready
6. Pre-meeting "gotcha" check — any open asks, promised follow-ups, action items from the last meeting with these people

Save outputs to: ~/claude-outputs/meeting-prep/{date}-{subject-slug}.md

Memory pattern:
- On first run, ask me for: my role, company, focus areas. Save to memory. Never re-ask.
- Maintain a "frequent attendees" file. If I've already met someone, reuse the research instead of re-doing it.
- Save my tone preference for the brief (default: executive bullets, max one page).

Critical rules:
- Output is always a file on disk, never just a chat reply
- Bullets, not paragraphs. Max one page.
- If you can't find reliable info on an attendee, say "limited public info" rather than guess.

Write SKILL.md with proper frontmatter (name, description, when_to_use). When done, show me the SKILL.md content.
Done when:
  • ~/.claude/skills/meeting-prep/SKILL.md exists
  • The skill asks for your profile on first run (and never again)
  • Run it on a real calendar invite and check that a brief lands in ~/claude-outputs/meeting-prep/
Notice the shape. Skill folder. Memory pattern. Outputs as files. Tone preferences. Same architecture as Job Hunt Copilot. Once you've seen the pattern twice, you own it.
